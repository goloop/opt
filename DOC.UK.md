## Ментальна модель

`opt` відображає аргументи командного рядка на Go-структуру — так само, як
`encoding/json` відображає JSON на структуру. Ви описуєте опції тегами структур,
викликаєте `Unmarshal` і читаєте типізовані поля.

Існують дві категорії аргументів:

- **Прапори** змінюють поведінку. Бувають *довгі* (`--host`) і *короткі* (`-p`),
  несуть значення або діють як перемикач.
- **Значення** — це дані: передані позиційно (`5 10 15`) або як значення прапора
  (`--host=localhost`).

Парсер дотримується конвенцій POSIX/getopt: короткі прапори можна групувати
(`-vp80`), довгі приймають `--flag value` чи `--flag=value`, `--` відділяє
кінцеві позиційні аргументи від прапорів, а булеві — це перемикачі, що ніколи не
поглинають наступний токен.

Оскільки відсутні прапори не чіпають поля (як відсутні поля JSON-документа),
звичне нашарування конфігурації виходить само собою: заповни структуру
дефолтами, наклади оточення, потім виклич `Unmarshal` - кожен етап
переозначає лише те, що явно називає, а тег `def` ніколи не б'є значення,
яке вже поставив попередній етап.

```go
import "github.com/goloop/opt/v2"
```

## Точки входу

```go
func Unmarshal(obj any) error
func UnmarshalArgs(obj any, args []string) error
```

`Unmarshal` парсить `os.Args` у структуру, на яку вказує `obj`. `UnmarshalArgs`
робить те саме для довільного зрізу — перший елемент вважається шляхом програми
(як `os.Args[0]`), що зручно для тестів, під-команд і REPL:

```go
var cfg Args
err := opt.UnmarshalArgs(&cfg, []string{"app", "--host", "x", "-p", "80"})
```

`Unmarshal` повертає всі помилки парсингу, з'єднані через `errors.Join` (не
звіряйтеся з текстом помилки). Він також може панікувати на *програмній*
помилці — див. [Паніка проти помилки](#паніка-проти-помилки).

## Теги структур

| Тег | Призначення | Дефолт |
|-----|-------------|--------|
| `opt`  | ім'я короткого чи довгого прапора; може нести модифікатори через кому, напр. `opt:"host,required"` | ім'я поля в kebab-case |
| `alt`  | альтернативне ім'я (коротке, якщо `opt` довге, і навпаки) | немає |
| `def`  | дефолт, що застосовується, коли прапора немає **і** поле досі має нульове значення | поле не чіпається |
| `sep`  | роздільник, що ділить значення-список | порожньо (один прапор на елемент) |
| `help` | короткий опис у згенерованій довідці | немає (приховано) |

Коли `opt` опущено, ім'я прапора — це ім'я поля, перетворене в kebab-case
(`UserName` → `--user-name`). `opt` і `alt` не можуть бути обидва довгими чи
обидва короткими — пара має бути одне коротке й одне довге.

Єдиний наразі підтримуваний модифікатор — `required`: опція має з'явитися в
командному рядку, інакше `Unmarshal` повертає помилку.

```go
type Args struct {
    Host    string   `opt:"H" alt:"host" def:"localhost" help:"host of the server"`
    Port    int      `opt:"port" alt:"p" def:"8080" help:"port of the server"`
    Verbose bool     `def:"true" help:"enable verbose mode"` // --verbose
    Configs []string `opt:"c" sep:","`
    DSN     string   `opt:"dsn,required"`
}
```

## Зарезервовані значення opt

Тег `opt` має чотири зарезервовані значення:

| Значення | Зміст |
|----------|-------|
| `-`     | повністю ігнорувати поле |
| `?`     | отримати згенерований текст довідки (поле має бути `string`) |
| `[]`    | отримати позиційні аргументи (поле має бути зрізом/масивом) |
| `0`,`1`,…,`N` | конкретний позиційний аргумент за індексом (індекс `0` — шлях програми) |

```go
type Args struct {
    Doc        string `opt:"?"`  // заповнюється текстом довідки
    FileName   string `opt:"1"`  // перший позиційний аргумент
    Positional []int  `opt:"[]"` // усі позиційні аргументи
}
```

## Підтримувані типи

`int`/`int8`…`int64`, `uint`/`uint8`…`uint64`, `float32`/`float64`, `string`,
`bool`, `time.Duration`, `url.URL`, вказівники на будь-який із них та масиви чи
зрізи будь-якого з них (напр. `*int`, `[]string`, `[2]*url.URL`). Від'ємні числа
приймаються як значення й позиційні аргументи.

Будь-який інший тип поля (`chan`, `map`, інші структури) — це програмна помилка й
викликає паніку.

## Правила парсингу

### Довгі прапори

Довгий прапор має два дефіси: `--host`. Імена — латинські літери/цифри з дефісами
для розбиття слів (`--user-name`), **нечутливі до регістру** (`--host` ==
`--HOST`). Значення йде через пробіл чи `=`: `--host localhost` ==
`--host=localhost`. Багатослівні значення потребують лапок: `--user="Smith J."`.

### Короткі прапори й групування

Короткий прапор має один дефіс: `-p`. Імена — лише латинські літери, **чутливі до
регістру** (`-h` ≠ `-H`). Значення йде з пробілом чи без: `-p 8080` == `-p8080`.

Короткі прапори можна групувати: `-vdp8080` — це `-v -d -p 8080`. Стережіться
випадкових дублікатів у групі — у `-vpv` кінцеве `v` стає значенням `-p`
(тобто `-v -p v`), бо щойно з'явився прапор зі значенням, решта групи — його
значення.

### Булеві перемикачі

Булевий прапор — це перемикач. Написання `--verbose` (чи `-v`) вмикає його й він
**ніколи** не поглинає наступний токен — точно як безаргументна опція в `getopt`.
Його відсутність лишає дефолт (false, якщо `def` не каже інакше).

Щоб явно виставити false, використайте префікс `no-` чи форму `=`:

| Ввід | `verbose` |
|------|-----------|
| `--verbose`, `-v`            | true |
| `--no-verbose`              | false |
| `--verbose=false`, `-v=false` | false |
| `--verbose false`           | true, а `false` стає позиційним аргументом |

Булеве значення має бути справжнім булевим літералом; `--debug=2` — помилка, а
`--flag=` (порожнє значення) означає нуль/false, а не true.

### Позиційні аргументи

Позиційні аргументи — це значення, що не належать прапору. Індекс `0` — шлях
програми (додається автоматично). Вони можуть бути зліва (перед першим прапором)
і справа (після значення останнього прапора), навіть водночас:

```
./app 5 10 --host localhost -d -- 15
```

Якщо останній прапор перед кінцевими позиційними — це перемикач (не бере
значення), відділіть позиційні через `--`, інакше перший з них буде прочитаний як
значення цього прапора. `--` означає «усе після мене — позиційне».

### Повторювані прапори й списки

Прапор, зіставлений зі зрізом/масивом, можна повторювати, а його значення
накопичуються:

```
./app -uJohn --user=Bob -u Roy   // []string{"John", "Bob", "Roy"}
```

З `sep` список можна також передати одним значенням (`-A23,25,27` з `sep:","`).
Повторення прапора, що **не** є списком, — не помилка: перемагає останнє значення.

## Згенерована довідка

Заповніть поле `string` з тегом `opt:"?"`, щоб захопити автозгенеровану довідку,
що друкується, коли встановлено ваш власний прапор `-h`/`--help`:

```
Options:
    -H, --host    host of the server;
    -d            debug mode;
    -h, --help    show application usage information;
    -p, --port    port of the server;
        --verbose enable verbose mode;
    -U            URL to the server.

Positional arguments:
The app takes an unlimited number of positional arguments.
```

Опції з порожнім тегом `help` опускаються з цього тексту. Довідка генерується
навіть коли парсинг зазнав невдачі, тож її можна надрукувати поруч із помилкою.

## Паніка проти помилки

Два режими відмови навмисно різні:

- **Паніка — проблема розробки.** Структура чи теги неправильні: `obj` — не
  вказівник на структуру; поле `opt:"?"` — не `string`; поле `opt:"[]"` — не
  список; поле має непідтримуваний тип структури/вказівника (окрім
  `url.URL`/`*url.URL`). Це не виправити під час виконання, тож вони панікують.

- **Помилка — проблема користувача.** Командний рядок недійсний: незадекларований
  прапор, значення, що не пасує типу поля, переповнення масиву, число поза
  діапазоном чи відсутня `required` опція. Вони повертаються, тож можна показати
  довідку й вийти охайно:

```go
switch err := opt.Unmarshal(&args); {
case err != nil:
    log.Fatalf("%v\n\nError: %v", args.Doc, err)
case args.Help:
    fmt.Println(args.Doc)
    os.Exit(0)
}
```

## Рецепти й поради

**Пара коротке + довге.** Покладіть одну форму в `opt`, іншу в `alt`
(`opt:"host" alt:"H"`); парсер прийме і `-H`, і `--host`.

**Обов'язкові опції.** Додайте модифікатор `required` (`opt:"dsn,required"`), щоб
відсутнє значення стало чіткою помилкою, а не тихим нулем.

**Тест без чіпання `os.Args`.** Кермуйте `UnmarshalArgs` літеральним зрізом
(пам'ятайте про провідний елемент — шлях програми), щоб юніт-тестувати парсинг.

**Збір списку двома способами.** Дайте полям-спискам `sep`, щоб викликачі могли
або повторити прапор (`-c a -c b`), або передати одне розділене значення
(`-c a,b`).

**Кінцеві позиційні після перемикача.** Завершуйте командний рядок через `--`
перед позиційними значеннями, коли останній прапор — булевий, щоб їх не поглинуло
як його значення.
